AI 受付アシスタント

Google スプレッドシート・Gmail・Google フォームと生成AIを組み合わせて、問い合わせの仕分け・通知・返信の下書き・記録・リマインドを自動化します。Google Apps Script（GAS：Google のサービス上で動くプログラム）で作っているため、サーバーや有料の自動化ツールは不要です。

こんなお悩みに

  • 問い合わせメールやフォームの回答を、毎朝ひとつずつ読んで担当者に振り分けている
  • クレームや障害の連絡に気づくのが遅れ、対応が後手に回ったことがある
  • 「来週中に」「月末までに」といった期限を見落としがち。担当者ごとの対応状況も見えにくい
  • 返信文を毎回ゼロから書いていて時間がかかる
  • 日報・週報のための件数集計が手作業になっている
  • 生成AIを使いたいが、個人情報をそのまま外部に送るのは避けたい。最終確認は人がしたい

できること

機能内容
受付Gmail を定期的に確認（既定は10分ごと。検索条件とラベルで対象を指定）。Google フォームの回答は送信時にすぐ処理します。
前処理引用文・署名を取り除き、メールアドレス・電話番号・郵便番号・住所・カード番号・氏名などを [メール1] のような記号に置き換えてから AI に送ります（設定で切り替え可）。
AI 判定分類・緊急度・要約・必要な対応・期限・タスク・返信案を受け取り、形式を検証します。失敗したら再試行し、それでもだめならキーワードのルールで分類します。
AI の切り替えClaude / OpenAI / Gemini を設定で切り替えられます。既定は小型で低価格のモデルです（モデル名は設定シートで変更可）。
期限の確認「来週中」などのあいまいな期限は日付に置き換えたうえで要確認と表示し、通知でも確認を促します。
通知分類×緊急度のルールで、Slack / Chatwork / メール / LINE（Messaging API）/ Google Chat に通知します。担当者へのメンションにも対応します。
返信の下書きGmail に返信の下書きだけを作ります（自動送信は既定でオフ）。
記録「ログ」シートに受信日時・送信者・件名・分類・緊急度・要約・担当者・状態（未対応／対応中／完了）・対応期限・下書きへのリンクを記録します。タスクは「タスク」シートへ。
リマインド・レポート期限超過・長時間未対応の案件を毎朝まとめて通知します。日報・週報・月報も自動で作ります（AI による3行の総評付き）。
安定運用二重処理の防止、Apps Script の実行時間の制限を見越した分割処理と自動再開、1日の実行時間の上限の監視と管理者への通知、エラーの記録。
コストの把握AI の呼び出し回数とトークン数（AI の利用量の単位）を月別に集計し、設定した単価から費用を推定します。
お試し「サンプルで試す」で、API キー（AI を使うための鍵）なしで全体の流れを確認できます（通知・下書きは実際には送信・作成しません）。

処理の流れ イメージ

ツールの仕様をもとに作成した図です。

  1. Gmail の新着メール10分ごとに確認
    Google フォームの送信送信時にすぐ処理
  2. 前処理引用・署名の除去／個人情報を記号に置き換え（マスキング）
  3. AI 判定分類・緊急度・要約・期限・返信案
  4. AI がエラーのとき再試行しても失敗したら、キーワードのルールで判定（「判定方法：ルール」と表示）
  5. 担当者・通知先を決める分類×緊急度のルール
  6. ログ・タスクシートに記録状態（未対応／対応中／完了）と対応期限も管理
  7. Gmail に返信の下書き記号を元の値に戻して、Google の中で作成
    担当者に通知Slack / Chatwork / メール / LINE / Google Chat
  8. 担当者が内容を確認して送信最終判断は人が行います
  9. 毎日：リマインドとレポート期限超過・未対応の案件、日報・週報・月報

デモ

このツールの画面画像は準備中です。以下の「マスキングの例」はツールの処理を架空のサンプル問い合わせで実際に動かした結果、「通知文」「ログシート」はツールの仕様をもとに作成したイメージです。人名・会社名・連絡先はすべて架空です。

マスキングの例（架空のサンプルで実際に処理した結果）

ツールに同梱している架空の問い合わせ（クレームの例）を、前処理とマスキングの処理に通した結果です。引用部分と署名は取り除かれ、電話番号・郵便番号・住所・差出人の名前が記号に置き換わっています。

建物名（「サンプルマンション101」）は検出されずに残っています。マスキングはパターンによる検出のため、すべての個人情報を確実に検出できるわけではありません。取引先名・契約番号など送りたくない語句は「追加マスキング語句」「追加マスキング正規表現（文字のパターン）」で指定できます。実際に AI に送られる本文は「サンプル結果」シートで確認できます。

通知文の例 イメージ

Slack・Chatwork・メール・LINE・Google Chat に、次のような本文で通知します（見積依頼をフォームで受け付けた場合の例）。

【問い合わせ】緊急度：中｜見積・購入相談
件名：見積依頼
送信者：中村 健一 <ken.nakamura@example.com>
受信：2026-11-02 10:15（フォーム）
担当：佐藤（営業）
要約：業務用プリンター10台と保守契約の見積依頼。社内の稟議に使用。
必要な対応：
・見積書を作成して送付する
期限：2026-11-13（推定・要確認 「来週中」）
⚠ 期限があいまいです。お客様への確認または期限の確定をお願いします。
返信下書き：Gmail に作成済み（送信前に内容を確認してください）
受付ID：（問い合わせごとの番号）
ログ：（スプレッドシートの該当行へのリンク）

通知に個人情報（送信者名など）を含めるかどうかは設定で選べます。件名などに含まれる <!channel> のようなメンション記法は、全員への通知にならないよう無害化します。

個人情報と安全対策

AI に送るもの

  • 件名
  • 本文（引用・署名を除き、個人情報を記号に置き換え、最大文字数で切り詰めたもの）
  • 受信日、種別（メール／フォーム）、判定のための指示文（会社名・分類名と説明）

AI に送らないもの

  • 送信者のメールアドレス・表示名
  • 添付ファイル
  • 同じスレッドの過去のやり取り（既定。設定で「はい」にした場合のみ、同じようにマスキングして送ります）
  • ログシートの内容（レポートの総評を除く）
心配なこと対策
記号と元の値の対応表実行中のメモリにだけ保持し、保存も送信もしません。返信の下書き・ログ・社内向けの通知を作るときに、Google の中で元の値に戻します。
API キー・Webhook URL（通知先の受け口）シートには書かず、スクリプトプロパティ（スクリプト専用の保管場所）に保存します。ただし、スクリプトの編集権限を持つ人は閲覧できるため、スプレッドシートの編集権限は必要な人だけに付与してください。
権限スプレッドシートは「このファイルだけ」の読み書き権限で動きます。必要な権限だけを明示しています。
本文に仕込まれた「指示」本文はデータとして渡し、中の指示に従わないよう AI に指示します。AI の出力は形式を固定し、値の種類・長さを検証してから使います。
数式の埋め込み= などで始まる文字列は、シートの数式として実行されないようにして書き込みます。
誤送信返信は下書きのみ。自動送信は既定でオフで、有効にしても厳しい条件付きです（下記）。

自動送信について：自動送信は既定でオフで、推奨していません。有効にした場合でも、許可した分類・緊急度「低」・AI 判定が成功・期限があいまいでない・返信文に記号が残っていない・Gmail で受信したメール、のすべてを満たす場合に限って送信します。AI が事実と異なる内容を書く可能性があり、送信したメールは取り消せないためです。

納品物と導入の流れ

納品物

  • お客様用に設定したスプレッドシート（メニュー「AI受付」から操作）
  • 設定ガイド（権限の許可、「このアプリは Google で確認されていません」と表示されたときの進め方、通知先の準備）
  • 運用マニュアル（日々の運用、障害対応、再処理、担当者の引き継ぎ）
  • セキュリティ資料（データの流れ、AI に送るデータ、マスキングの限界、API キーの管理）

費用について

  • Google スプレッドシート・Gmail・Google フォーム・Apps Script は、Google アカウント（Google Workspace）の範囲内で使えます。
  • 生成AIの API 利用料は、処理する件数と文字数に応じた従量課金です。お客様のアカウントでご契約いただき、単価は各社の公式料金表でご確認ください。
  • 実際の利用量は「コスト」シートで月別に確認できます。

導入の流れ

  1. ヒアリング

    問い合わせの種類・件数、通知先、担当者、個人情報の扱いの方針を確認します（目安 30分〜1時間）。

  2. 初期構築

    テンプレートのコピー、初期設定、分類・通知ルール・署名を設定します（目安 半日）。

  3. 試験運用

    サンプルと実際のメールで判定結果を確認し、分類の説明文やキーワードを調整します（目安 1〜2週間）。

  4. 本番運用

    自動処理を始めます。日報・週報・コストを見ながら改善します。

  5. 引き継ぎ

    運用マニュアルに沿って、担当者へ引き継ぎます（目安 1時間）。

納品後2週間は、不具合や設定上の問題に対応します。目安の時間は、問い合わせの種類や通知先の数によって変わります。

対応しないこと・注意点

  • AI の判定の精度 100% は保証できません。分類・期限・返信内容の最終判断と送信は、必ず担当者が行う運用を前提にしています。
  • 返信メールの完全自動送信を前提とした運用（設定で有効にはできますが、推奨しません）
  • 添付ファイル（PDF・画像など）の内容の読み取り
  • Gmail 以外のメールサーバーや、Slack・Chatwork のメッセージの取り込み
  • 送信者ごとの過去の履歴を踏まえた判定（判定は1通ずつ行います。同じスレッド内の過去のやり取りは、設定で AI に渡せます）
  • 大量配信の処理（1日数千件規模）。Apps Script の利用上限の範囲内での運用を想定しています
  • 個人情報の完全な検出（マスキングはパターンによる検出です。本文中の第三者の氏名や、都道府県名などを含まない住所は残る場合があります）
  • Google による「確認済みアプリ」としての公開（社内利用を前提にしています）

病歴などの要配慮個人情報を含む問い合わせが想定される場合は、AI 判定を使わない（キーワードのルールだけで分類する）運用もご検討ください。

AI 事業者に送ったデータの保存期間や学習への利用の有無は、事業者・契約プランによって異なります。導入前に、各社の利用規約・データ利用ポリシーをご確認ください。

よくある質問

どの AI を使えますか？

Claude（Anthropic）・OpenAI・Gemini（Google）を設定で切り替えられます。AI を使わず、キーワードのルールだけで分類する設定もできます。

返信は自動で送られてしまいませんか？

送られません。既定では Gmail に下書きを作るだけで、送信は担当者が内容を確認して行います。

API キーがなくても試せますか？

はい。メニューの「サンプルで試す」で、API キーなしで全体の流れを確認できます（通知・下書きは実際には送信・作成しません）。

「このアプリは Google で確認されていません」と表示されます。

社内利用のスクリプト（一般公開していないもの）のため、権限の確認画面でこの表示が出ます。進め方は設定ガイドで説明しています。

問い合わせが多い日でも止まりませんか？

Apps Script には1回あたり・1日あたりの実行時間の上限があります。上限を見越して処理を分割し、途中で止まっても次回に続きから再開します。1日の上限の70%で管理者に警告、90%で処理件数を絞ってレポートなどを止め、98%で当日の処理を止めます。

あとから分類や通知先を変えられますか？

はい。「分類」「通知先」「担当者」「通知ルール」のシートを編集して変更できます。「設定チェック」で設定の誤りを確認できます。
